# OmniTranslate 功能评估（2026-11-27）

本次为源码对照与设计评估，没有把下列功能直接并入插件。对照基线：我们的 v0.4.30（bf12e20）；对方 main 为 aa4aa1c68a75d061b5e63feff78227ee323d481b。未运行对方插件或测量真实服务延迟，不能把功能列表当成性能结论。

## 建议优先做

| 功能 | 用户能得到什么 | 实现判断 |
| --- | --- | --- |
| 接入 Win顺官方截图的翻译入口 | 用官方截图按钮时也能调用我们的渠道、缓存和降级 | 必做，成本中低；必须补齐独立协议入口，不能只加清单字段 |
| AI 流式显示及关闭思考适配 | 先看到已有译文；支持的模型可少花时间做无关推理 | 高优先级，成本中高；逐句进度不同于逐字流式；截图只在完整分块结束后覆盖图像 |
| 翻译历史、收藏、Anki / CSV 导出 | 查过的内容可以复习、找回和做卡片 | 高实用性，成本中；建议复制/收藏时记录，提供关闭、清除和数量限制 |
| 扩展文本预处理 | PDF 粘贴接行、冒号语言前缀、可配置常用语言对 | 成本低到中；代码、表格和列表不能默认合并 |
| 编程命名 | 拆解 userAccountBalance；生成 userAccountBalance / user_account_balance 等 | 成本低到中，适合开发用途；独立模式避免改写普通翻译 |
| 语音朗读 | 点击听原文或译文 | 成本中；优先复用 Windows 已安装语音，语言覆盖取决于系统语音 |

## 可以支持，但作为可选项

- 多渠道对照：由用户主动选择比较两家，先展示先返回的结果。不要每次自动请求所有渠道，否则请求量、付费和限流机会都会增加。
- 新渠道：Anthropic 原生协议、本地 Ollama、百度/腾讯/火山官方翻译可以按实际需求补。我们已有多个 OpenAI 兼容渠道及模型；增加名字不等于增加新能力。对方“微软免 Key”使用的就是我们已有的 Edge 接口；其 Google 使用 Google Cloud API Key，不能据此推断我们的免密钥入口会更快或更稳定。
- 输入框原位替换：有用途，但应作为独立动作，默认关闭。翻译期间可能切换窗口、移动光标或修改选区，写回前必须重新验证目标，失败时留在结果窗口供复制。

## issue #2：建议支持

作者提出的是翻译提供者协议：清单顶层 `translate` 指向一个命令，官方截图把 OCR 文字交给它；最终结果第一项的 `copy` 是译文，`id=setup` 表示需要配置，失败后宿主尝试下一插件。Win顺 0.32.0 起支持。

我们已具备异步查询、成功译文在前、copy 字段、渠道降级和取消。当前还有三处不能直接接：

1. 现有搜索查询超过 1200 字会返回“打开长文面板”，官方截图需要直接拿到译文。
2. 官方截图要求多行原文按行对应返回；我们自有截图的段内接行不能套到这个协议上。可内部合并上下文，但最终必须恢复与输入一致的行对应。
3. 需明确配置错误、失败和查询总时限。宿主文档规定查询最多 10 秒；当前清单填 25000 不能当成宿主真的会等待 25 秒。不能在此路径无限串行尝试降级渠道。

建议新增专用 host-translate 命令，复用 Services，不打开窗口、不读剪贴板、不写历史；保留现有截图入口。补充多行、长文、首渠道失败、取消/超时及官方截图端到端验证。接入让用户多一个入口，并不会自动改变 OCR 引擎或解决 429。

## 与取词兼容有关的额外发现

对方 selection.py 使用模拟 Ctrl+C / Ctrl+V，备份和恢复的只是剪贴板文本；不能直接当成保留图片、文件、富文本格式的方案。我们应保留当前不模拟复制的被动图标读取。

Win顺 新版提供官方 selected_text 工具，copy:true 可在用户按快捷键时由宿主负责复制与恢复，值得作为可选兼容路径。但它最多返回 4000 字，普通接口会跳过 Chromium/Firefox，管理员目标也有限制；新增 selection:read 权限需要最低 0.41.0，复制回退需要 0.42.0。不能取代我们的长选区与管理员读取，也不能宣称它已解决 Fluxdo；需实际验证。

## 不需要重复引入

免费 Edge、有道词典、缓存、语言识别、长文面板、按句进度、手动换渠道和失败降级已有基础。对方的 PDF 接行算法还会删除某些行尾连字符，我们刚修好的 1.25-bit / 30B-A3B 保留策略应继续保留。

对方仓库为 MIT，多个文件标注算法来自 KittyTools。真正移植代码时应逐项核查来源并保留对应版权和许可；我们的实现继续采用原生 C++ / Qt，不增加 Python 运行依赖。
