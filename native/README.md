# 截图翻译 0.4.0：原生版构建与验证

原生 C++ / Qt Quick 版本，运行时不需要 Python、PySide6、PowerShell OCR 脚本或另装 Qt。
小型启动器只从本插件的 `runtime/` 加载随包 Qt，系统 Windows OCR 在后台线程识别图片。
支持 Windows 10/11 x64、WinShun 0.22.0+ 和至少一种 Windows OCR 语言包。
构建与分发使用 Qt 6.10.0 公共 API；运行时不从宿主目录加载 Qt。

原生 EXE / DLL 按官方“未审核的原生插件”类别提交，最低宿主版本为 0.22.0。
管理员插件自带运行库，不声明 `runtime.qt: host`；代码审核状态以官方索引为准。
本包沿用社区 ID `iuuuuuuuu.screenshot-translate`。

## 安装和回退

在 WinShun 设置 → 插件 → 从压缩包安装，选择
`iuuuuuuuu.screenshot-translate-0.4.0.wsplugin`。运行时不检查或启动 Python。
包内包括启动器、应用 DLL、Qt/Visual C++ 运行库、许可和文档；DLL 内包含 QML 控件与授权图标字体。
现有渠道、热键、代理、偏好和 DPAPI 密钥格式保持兼容，不迁移或删除用户的数据目录。

本地候选版的安装脚本和备份仍用于历史回退。公开版使用 WinShun 的压缩包安装流程。
回退时可安装原 v0.3.3 包及其 Python 依赖，或恢复已保存的完整备份。
不要同时启用历史 `winshun.screenshot-translate` 和当前社区 ID。

### 读取以管理员身份运行的软件

本包声明 WinShun 的 `elevated` 权限。以管理员身份启动 WinShun 后，在设置 → 插件 →
截图翻译中允许新增的“跟随 Win顺 的管理员权限”，并点击“确认”（如果卡片提示需要确认）。
WinShun 会创建受保护的插件副本并重新启动插件，名称旁出现管理员盾牌后，再回到目标软件
选中文字、按划词快捷键。可以继续保留 Codex 等目标软件的管理员运行方式。

普通启动 WinShun 时，插件仍以普通权限工作；不会自行弹出 UAC。管理员启动但未确认副本时
也仍是普通权限。更新新增权限可能使插件暂时等待重新启用；请在插件页允许新权限。
手动更新插件后，WinShun 可能要求重新确认管理员副本。固定窗口的后续选区读取继承插件
当前权限，无需每次授权。管理员权限不代替应用的选区接口；未提供接口的界面可用鼠标 OCR。
启动日志中的 `selection-reader=administrator` / `standard` 表示插件实际运行权限。

## 界面与操作

- `Alt+Shift+T` / `jst` 框选；`Ctrl+Enter` 全屏；`Shift+Enter` 当前窗口。
- 宿主支持时使用热键托管；独立插件宿主不提供此能力时，沿用官方截图插件的
  Windows RegisterHotKey 兼容方式。修改设置会释放旧热键并重新注册。
- `Alt+Shift+C` / `jft` 剪贴板或直接输入文字翻译；`Alt+Shift+W` 划词热键读取选中文字。
- 剪贴板热键立即在鼠标附近打开小词义窗口，原文、译文、加载和错误均在窗口中显示。
  划词热键在实际选区旁打开同一窗口；点击图钉后位置固定，新的非空选区每 450ms
  后台检查并自动更新，关闭即停止跟随。拖动标题只移动位置，不会自动固定。
- `Alt+Shift+O` 是鼠标指词 OCR 默认热键，可在 WinShun 基础插件设置中修改或清空。
  无需选中，Windows OCR 读取鼠标处的短句，在句末标点或明显间距处停止，
  自动换行时按行距、字号与左侧对齐连接同一段落的相邻行，最多连接 4 行；
  独立单词仍可识别，不跨空行、列表条目或相邻栏。无标点的长段落取鼠标附近
  最多 48 个 OCR 词块、240 个字符，窗口显示在鼠标附近。
  按字符间距拼接 OCR 词块，避免小字号英文单词被错误插入空格，同时保留实际词间空格。
  小字号英文会按屏幕像素定位连续片段，再局部放大精读；OCR 漏字留下的间隔不会直接截断取句。
  精读保留原先已读出的完整词和大小写，并受周围其他文字体系、真实空白及句末边界约束。
  跨行片段先在内存中按阅读顺序拼接像素，再精读换行两端，不改变屏幕内容。
  中英文等混排时，停在少数语言上只取鼠标所在的连续片段，停在主要语言上保留整句，
  不把隔着中文的两个英文片段连起来。主次按文字系统和近似字符宽度判断；没有明显多数，
  或不同语言使用同一字母体系时保留整句。日文汉字与假名作为同一文字组处理。
  不提供 UI Automation 选区的应用可使用这个入口。划词热键默认 `Alt+Shift+W`，
  已自定义的热键和明确清空的设置优先。
- 词义窗不抢原应用焦点，未固定时点击外部关闭，不受截图贴图的关闭设置影响；
  固定时保留，复制、重试、关闭使用 WinShun 控件和图标。窗口与截图任务分别取消，
  新的词义请求立即取代旧请求；固定状态只在本次窗口开启期间保留。
  “重试”保留原请求的窗口和取词位置，弹窗不会跟随重试按钮处的鼠标逐次下移。
- 鼠标 OCR、剪贴板和划词窗口的原文默认可编辑，直接点击原文即可修改；
  原文保持正文样式和面板底色，聚焦时只有文字光标闪烁，不显示下划线或输入框高亮。
  自动翻译、译文和加载状态始终保留。失去焦点自动提交，Enter 立即提交，Shift+Enter 换行，
  有草稿时 Esc 或原文末尾的还原图标放弃修改；提交后可继续编辑，无需切换模式。
  打开窗口时不抢焦点，点击原文后才接受键盘输入；有未提交的修改时暂停固定窗口
  的选区跟随，提交或还原后恢复。仅点击原文不会暂停跟随，旧请求不会覆盖新的译文。
- 多屏分别创建完整原生蒙版，采用物理坐标；选区图像一直保持原像素尺寸。
- 框选画面在后台 DIB 合成，每帧仅一次 BitBlt 显示；选区直接按原坐标复制，
  连续拖动不先刷灰，也不把整屏画面缩放到选区。
- 识别和翻译期间显示动画；工具条、设置、提示和语言菜单复用 WinShun 控件和 Phosphor 图标。
- 加载提示随贴图尺寸调整：单词小选区显示 24px 动画，小图使用简短文字，
  较大区域使用 12px 状态文字。小选区的提示放在边缘外，拖动和缩放时同步跟随。
- 贴图为 WinShun 的 Win32 分层窗口，拖动同步工具条，滚轮缩放，Ctrl+滚轮调透明度。
  Esc、双击或关闭按钮立即关闭；点击外部关闭可配置，内部菜单和设置不触发关闭。
- 对照上下排列，默认译文在上，顺序可在基础插件设置中修改。右键可复制、对照、保存或重新截图。
  大图可通过滚轮缩小；长译文可在“完整译文”窗口查看、选中并复制。
- 小型 QML 控件采用软件绘制，不建立每个窗口的 D3D 堆；宿主选择 GPU 渲染不影响这些控件。

主渠道、共用代理、热键和偏好仍由 WinShun 基础插件面板管理。渠道配置页为平铺换行标签，
浏览和保存配置不会切换主渠道。宿主基础卡片的长渠道组是否平铺仍由宿主版本决定；
现有本地宿主修复见 `.host/`，原生包不修改 WinShun.exe。

## 服务和数据

渠道包括 MyMemory、Google、Edge/Bing、translate.js、搜狗、有道、ECDICT、Microsoft、DeepL、
AI 翻译。OpenAI、DeepSeek、豆包、混元等兼容服务统一填写 URL、API 密钥和模型名；旧配置自动迁移。
Google 保留浏览器请求头及多客户端重试；Edge 缓存七分钟凭据，取票
失败后尝试 Bing。MyMemory 和 Google 的文字块最多并行四个；全部渠道测试最多并行三个，
未配置密钥的付费渠道跳过，测试不自动降级或改变主渠道。

设置窗口默认进入首页，展示所有渠道、逐项 / 全部测试、耗时、权重与冷却时间。
手动队列支持拖动手柄或上下按钮；自动模式优先排列可用渠道，再按权重从高到低尝试。
主渠道始终在前；自动降级关闭时仅尝试主渠道。保存将渠道配置与队列原子写入同一份 `services.json`，
取消丢弃草稿；切换自动模式不会丢失手动顺序。旧配置默认保留原来的备用顺序。

权重按近期成功率（80%）和成功响应速度（20%）计算。未测渠道初始为 50；成功率与耗时采用
新样本占 30% 的指数平滑，成功率初始先验为 75%，速度分量为 `1000 / (1000 + 毫秒)`。
同分沿用手动顺序。测试与实际请求都记录结果，失败进入原有冷却；显式测试可以立即重试冷却渠道，
成功后解除冷却。词典不支持的文本、未配置和取消不计入统计；配置指纹变化使用独立统计。
权重与失败记忆保存在 `service-health.json`，不保存请求正文、密钥或翻译结果。

搜狗使用公开网页的服务端结果，有道支持免费英汉查词与官方 v3 签名翻译。ECDICT 内置 770,611 个词条，
按文件索引查找，无网络或 Python 依赖；未收录词和长句可降级，但不标记词典服务故障。

自动降级默认开启。失败时间和配置指纹沿用 `service-health.json`，默认十分钟、
可配置 1–1440 分钟；恢复间隔到后在下一次翻译重试，修改地址、代理或密钥立即重试。
修改 AI 模型、有道应用 ID 或 Azure 区域也会立即重试。
网络请求有总时限并每 25ms 检查取消；关闭窗口立即取消任务，不等待 HTTP 超时。
使用官方翻译插件同类的 Windows WinHTTP 异步请求和系统 HTTPS，宿主不需要 Qt TLS 插件。
划词在显示弹窗前记录原窗口，标准 Edit / RichEdit 控件读取公开选区消息；其他应用用
UI Automation，依次查找原控件、鼠标处、焦点及页面内部支持文本选区的容器，兼容
Chromium/Electron 中焦点停留在外层容器的情况。读取使用无窗口的原生辅助进程，
2.2 秒超时或关闭时回收；单次应用卡住不会阻塞后续划词。同一时间至多一次读取，
不模拟复制快捷键、不改剪贴板、不占用截图入口。未公开选区的应用仍可使用鼠标 OCR。
读取失败且检测到权限差异或访问限制时，会提示以管理员身份启动 WinShun 并确认本插件权限。
选区辅助进程直接继承插件权限；授权由 WinShun 管理，普通插件不另行启动提权读取器。

截图留在本机内存；仅 OCR 文字发送到选择或降级的服务。密钥继续由当前用户的 Windows
DPAPI 加密。日志不记录截图、OCR 文字、凭据或服务响应正文。免费入口仍可能限流或失效。
长译文在原区域可能放不下；完整译文窗保留全部文字。复杂背景和不完整的 OCR 框可能留有残影。

## 构建和验证

### 渠道标记与闲置内存

界面渠道名称来自每次请求返回的实际 `provider`，降级标记来自 `fallback`；截图工具栏不截断渠道名称，
词义窗在底部操作旁显示，完整译文和关键字结果同样标记。不会将主渠道配置当作成功结果的来源。
降级时使用 WinShun 的 `caution` 提醒色，正常结果保持默认颜色；每次新请求清除旧降级状态。
渠道悬浮提示使用独立、不抢焦点的 QtQuick 窗口，避免被 32px 工具栏裁切，显示备选渠道及恢复规则。
词义窗修改原文后，在失去焦点时短暂延后提交，先让还原 / 关闭操作完成；空白、未修改和输入法组词不会提交。
Enter 仍可立即提交，末尾的还原图标恢复当前结果对应的原文，避免底部重复按钮占用空间。

参考 WinShun `platform/IdleTrim.cpp` 的空闲回收策略：关闭后保留词义窗 20 秒用于连续取词，
空闲时销毁所有不用的 QML 引擎、释放图片和 QPixmap 缓存，延后等待 Qt 删除完成，再由后台线程调用
`SetProcessWorkingSetSizeEx` 交还驻留页。没有退出插件或释放快捷键，不定时重启进程。
窗口可见、固定词义窗、截图 / OCR / 网络 / 选区任务均阻止回收；检测睡眠恢复后保持页面，直到再次使用。
工作集回收与真正释放对象分别记录，不能把提交内存下降与驻留内存下降混为一谈。

`python -B native/test_native.py --memory --build <目录> --runtime <Qt目录> --output <输出目录>`
在独立桌面依次完成复制翻译、真实 Windows OCR 截图翻译、设置开关，等待真实闲置延迟，
记录各阶段总工作集、私有工作集、提交大小、句柄数和闲置后重新打开耗时；另检查固定窗与睡眠保护。

开发构建需要 Python 3。`build.ps1` 自动下载固定提交的 ECDICT 数据、校验 SHA-256 并生成 `data/ecdict.bin`。
已有词库通过校验后复用，不会重复下载；`package.py` 会将索引、来源校验记录和 MIT 许可一起打包。
用户安装后不需要 Python，也无需首次下载词库。完整 UI 测试应串行运行，避免测试热键互相冲突。

```powershell
.\native\build.ps1 -QtRoot <Qt6.10.0-msvc2022_64> -VsRoot <VisualStudio> -Output <构建目录>
python -B native/package.py --build <构建目录> --qt-root <Qt目录> --vs-root <VisualStudio>
# package.json 中的 stage 是完整待发布目录；开发中可加 --allow-dirty，仅供本地验证。
python -B native/test_native.py --build <stage目录> --runtime <stage目录>/runtime
python -B native/test_native_standard.py --build <stage目录> --runtime <stage目录>/runtime --output .test-output/native-standard
python -B native/test_native.py --build <构建目录> --runtime <stage目录>/runtime --core
```

Python 仅用于开发时打包和测试。测试子进程的 PATH 不含 Python，公开包验证使用
包内 Qt。UI 测试在从不切换到前台的独立桌面运行，使用合成截图、
本地模拟服务和真实 Windows OCR；真实 Win32 窗口检查双屏蒙版、贴图像素、对照、
菜单、关闭按钮、原始输入线程和热键协议。独立桌面不提供桌面 BitBlt，截图像素注入
仅存在于受独立桌面约束的预览入口；正常入口始终使用 Win32 BitBlt 抓屏。
`--gpu` 验证宿主 GPU 设置下的小控件软件渲染兼容性。
`test_native_standard.py` 从管理员开发终端运行，使用与 WinShun 相同方式移除管理员组、
特权并降低完整性的令牌，验证普通权限兼容性；只调整测试临时目录和测试桌面的权限。
`python -B native/test_selection_browser.py --electron <Electron.exe>` 可选验证真实 Chromium
页面的选区读取：在独立桌面用临时配置打开本地页面，焦点留在无关输入框，检查嵌套
文本容器中的完整选区。`--build <目录>` 可指定安装包入口；不操作当前浏览器或 Codex。
`python -B native/test_native.py --ocr-image <本地图片> --output <输出目录>`
在独立桌面读取指定图片，输出 OCR 词块坐标和各词块中心对应的短句，便于排查识别问题；
图片和文字不上传翻译服务。小字号英文词内间距和真实空格另有几何及原生弹窗回归验证。
可加 `--ocr-points "x,y;x,y"` 输出各指定坐标经过完整指词识别后的结果和耗时。
`--pointer-fixture <本地 JSON>` 可为弹窗回归加入真实截图像素：JSON 数组每项包含
`image`（本地图片绝对路径）和 `points`（含 `x`、`y`、`expected` 的数组）；
由私有桌面的捕获接口注入图片，真实 Windows OCR 结果经本地模拟翻译服务显示在弹窗中。

核心验证覆盖九个服务请求格式、UTF-8 分块、加号和百分号、DPAPI 双向兼容、
失败记忆、恢复、配置变化和取消。Edge 的在线认证和 Bing 入口另用合成文字验证。
付费渠道仅测试本地协议模拟，不使用真实用户密钥计费。
