# 截图翻译 0.4.41：原生版构建与验证

0.4.41 修复划词结果窗口使用文档顺序的选区边界而跳到尾部：点击、悬停、快捷键和异步结果都保留捕获的鼠标锚点，新选区清除旧拖动/重试位置。悬停开关直接显示于首页顶部，小窗口自动换行。`--selection-hover` 同时验证三种入口、正反向位置、多个屏幕、边缘避让、结果扩展以及折叠设置下开关可见。

0.4.40 增加默认关闭的 `selectionIconHoverTranslate`。保存后作用于小译图标；进入图标停留 350 ms 后共用主动完整取词路径，移出、按下、隐藏、关闭开关均停止计时。后端再次检查原窗口、图标有效期及启用状态。`--selection-hover` 验证默认关闭、设置保存、移出/隐藏/换窗口取消、完整选区复核及只请求一次；发布流水线运行同一专项。

0.4.39 修复多进程软件的复制来源识别：主窗口与剪贴板代理进程不必是同一个 PID，但必须在已核实的进程父子链上，且创建时间匹配；进程号复用、同名无关程序和兄弟进程均不放行。主动复制与手动复制接续共用规则。`--selection-release` 增加真实子进程复制、同名无关进程拒绝、取消还原及新复制优先测试；`native_tests --selection-owner-probe <HWND>` 只核对窗口/剪贴板进程元数据，不读取或修改剪贴板文字。

0.4.38 增加默认关闭的 AI 少量上下文：`TranslationContext` 延迟到 AI 候选才读取，跨模型复用一次结果；`SelectionContext.cpp` 使用隔离进程、原窗口/进程校验、完整选区匹配、字符边界和时间上限。UIA 只扩展选区附近范围；Firefox IA2 读取同一节点的附近偏移，不展开整个页面。标准 EDIT 只允许读取至多 4000 字的小字段，长字段交给 UIA 或跳过。缓存包含上下文摘要键，健康状态不受上下文改变影响；上下文不进入历史或磁盘。

`--core` 覆盖关闭/非 AI 不读取、600 字默认和上限、Unicode、缓存隔离、取消和不可用回退；`--ai-models` 同时覆盖设置保存、真实隔离 EDIT 读取、预览与编辑/关闭失效。`test_selection_firefox.py --context` 在新浏览器配置中覆盖正反向选词、首尾、Unicode 和错配，发布流水线同时运行。

0.4.37 增加模型列表发现、异步取消、搜索多选和独立冷却 UI；核心测试验证地址归一化、去重、错误/重定向/取消、冷却持久化和重置。`native_tests --ai-smoke <endpoint>` 从标准输入读取测试密钥，仅输出模型数量、时间和通过状态，使用临时数据目录验证流式/普通翻译，不输出原密钥或译文。普通 UI 测试在私有桌面使用只读选区夹具，真实复制仍使用发布专用的可销毁 Windows runner。

模型页面可独立验证：`python -B native/test_native.py --build <build> --runtime <runtime> --ai-models --output <report-dir>`。与完整界面回归共用相同断言，不依赖测试机的中文 OCR 语言包与混排识别结果；发布流水线运行此专项、原生核心及 Firefox/剪贴板专项，完整 OCR 界面回归使用本机 Win顺运行时验证。

0.4.36 将主动取词统一到 `readSelectionForTranslation`：原窗口复制消息 → 辅助功能取词 → 有选区且焦点未变时 Ctrl+Insert → 手动复制接续。原生复制和快捷键共用格式备份、序列校验、还原与取消处理；成功方式按进程生命周期和控件类型缓存十分钟。被动图标与固定跟随保持只读。

0.4.35 修复 Firefox 跨 Shadow DOM 组件拖选时辅助功能选区与屏幕实际选区不一致的问题。主动翻译改用浏览器原生复制，并还原原剪贴板；真实鼠标事件回归覆盖正反向拖选、快捷键和小译图标。

0.4.32 的 `--core` 增加真实 SSE 分包、中文 UTF-8、思考过滤、断流/截断、400 兼容、429 单次请求、长文流式顺序、历史去重/上限/关闭/导出、PDF/前缀/命名和静音 SAPI 合成回归。SAPI 测试输出到内存，禁止播放到用户设备。完整 UI 回归增加历史收藏/打开、PDF 单次目标语言、命名、流式首字和静音朗读状态；全部使用私有桌面和本地服务夹具。

Firefox 选区回归：`python -B native/test_selection_firefox.py --driver <geckodriver.exe> --firefox <firefox.exe> --build <build-or-stage> --output <report-dir>`。需要开发环境的 requests；使用独立桌面、全新浏览器配置和本地合成文本，检查首次读取、未重新划词的重复读取、无关输入框焦点、主屏/副屏及辅助进程退出。`--without-primer` 用于复现未提前启用接口时的漏报。`--native-copy --icon-click --case mouse-shadow-forward --case mouse-shadow-reverse` 使用测试浏览器的受信任鼠标事件复现跨 Shadow DOM 拖选，分别验证完整复制、小译和快捷键共用流程；主动复制会短暂使用并还原现有剪贴板，测试只记录原内容的校验值。普通回归仍为只读。辅助进程只准备 Firefox 文档接口，不修改浏览器设置或复制文字；日志默认关闭，`ST_SELECTION_TRACE=1` 仅记录读取阶段和耗时。

原生 C++ / Qt Quick 版本，运行时不需要 Python、PySide6、PowerShell OCR 脚本或另装 Qt。
小型启动器从 WinShun runner 提供的 `WS_QT_DIR` 加载宿主 Qt，系统 Windows OCR 在后台线程识别图片。
支持 Windows 10/11 x64、WinShun 0.23.0+ 和至少一种 Windows OCR 语言包。
构建使用 Qt 6.12.0 公共 API；运行时接受宿主 Qt 6.12.x，禁止从 PATH 或旧版随包 Qt 回退。

原生 EXE / DLL 按官方“未审核的原生插件”类别提交，最低宿主版本为 0.23.0。
清单声明 `runtime.qt: host` 与 `runtime.qtVersion: 6.12.0`，保留 `elevated`；代码审核状态以官方索引为准。
本包沿用社区 ID `iuuuuuuuu.screenshot-translate`。

包内不含 Qt DLL、平台插件、QML 运行库或 `qt.conf`。字体放在插件自身 `fonts/`；共享 Qt 目录只读。选区工作进程继承 runner 提供的环境。

## 安装和回退

在 WinShun 设置 → 插件 → 从压缩包安装，选择
`iuuuuuuuu.screenshot-translate-0.4.41.wsplugin`。运行时不检查或启动 Python。
包内包括启动器、应用 DLL、少量 Visual C++ 依赖、许可和文档；DLL 内包含 QML 控件与授权图标字体。
现有渠道、热键、代理、偏好和 DPAPI 密钥格式保持兼容，不迁移或删除用户的数据目录。

本地候选版的安装脚本和备份仍用于历史回退。公开版使用 WinShun 的压缩包安装流程。
回退时可安装原 v0.4.6 自带 Qt 包，或恢复已保存的完整备份。
不要同时启用历史 `winshun.screenshot-translate` 和当前社区 ID。

### 读取以管理员身份运行的软件

本包声明 WinShun 的 `elevated` 权限。以管理员身份启动 WinShun 后，在设置 → 插件 →
截图翻译中允许新增的“跟随 Win顺 的管理员权限”，并点击“确认”（如果卡片提示需要确认）。
WinShun 会创建受保护的插件副本并重新启动插件，名称旁出现管理员盾牌后，再回到目标软件
选中文字、按划词快捷键。可以继续保留 Codex 等目标软件的管理员运行方式。

普通启动 WinShun 时，插件仍以普通权限工作；不会自行弹出 UAC。管理员启动但未确认副本时
也仍是普通权限。更新新增权限可能使插件暂时等待重新启用；请在插件页允许新权限。
手动更新插件后，WinShun 可能要求重新确认管理员副本。固定窗口的后续选区读取继承插件
当前权限，无需每次授权。管理员权限不代替应用的选区接口；未提供接口的界面可用鼠标 OCR。
启动日志中的 `selection-reader=administrator` / `standard` 表示插件实际运行权限。

## 界面与操作

- 设置、独立翻译面板、历史与收藏各自记忆窗口大小，记录在数据目录的 `window-sizes.json`，调整后自动保存，重启后恢复。最大化单独记录，还原时使用最后的普通尺寸；换到较小屏幕时按当前可用区域收拢。
- 后续新增可调整大小的独立窗口，必须使用共享 `WindowFrame`，设置唯一的 `windowSizeKey`，并通过 `WindowSizeMemory::show` 打开。`App::view` 自动接入保存；不同窗口不能共用 key，也不要在打开时重新写死尺寸。划词、剪贴板翻译、鼠标 OCR 等 `AdaptiveWindow` 小窗不接入此规则，继续由内容和屏幕大小决定尺寸。

- `Alt+Shift+T` / `jst` 框选；`Ctrl+Enter` 全屏；`Shift+Enter` 当前窗口。
- 宿主支持时使用热键托管；独立插件宿主不提供此能力时，沿用官方截图插件的
  Windows RegisterHotKey 兼容方式。修改设置会释放旧热键并重新注册。
- `Alt+Shift+C` / `jft` 剪贴板或直接输入文字翻译；`Alt+Shift+W` 划词热键读取选中文字。
- 剪贴板热键立即在鼠标附近打开小词义窗口，原文、译文、加载和错误均在窗口中显示。
  划词热键在实际选区旁打开同一窗口；点击图钉后位置固定，新的非空选区每 450ms
  后台检查并自动更新，关闭即停止跟随。拖动标题只移动位置，不会自动固定。
- 原文默认最多三行，超出省略；点击原文展开并进入编辑。原文和译文分别滚动，右侧收起按钮保持固定，收起时提交修改。底部渠道菜单可选择服务或具体 AI 模型，只影响当前弹窗；“自动”沿用全局设置，显式选择继续遵循缓存、限流和冷却。圆角使用原生窗口裁剪，轻量动画遵循系统开关。
- `Alt+Shift+O` 是鼠标指词 OCR 默认热键，可在 WinShun 基础插件设置中修改或清空。
  无需选中，Windows OCR 读取鼠标处的短句，在句末标点或明显间距处停止，
  自动换行时按行距、字号与左侧对齐连接同一段落的相邻行，最多连接 4 行；
  独立单词仍可识别，不跨空行、列表条目或相邻栏。无标点的长段落取鼠标附近
  最多 48 个 OCR 词块、240 个字符，窗口显示在鼠标附近。
  按字符间距拼接 OCR 词块，避免小字号英文单词被错误插入空格，同时保留实际词间空格。
  小字号英文会按屏幕像素定位连续片段，再局部放大精读；OCR 漏字留下的间隔不会直接截断取句。
  精读保留原先已读出的完整词和大小写，并受周围其他文字体系、真实空白及句末边界约束。
  跨行片段先在内存中按阅读顺序拼接像素，再精读换行两端，不改变屏幕内容。
  中英文等混排时，停在少数语言上只取鼠标所在的连续片段，停在主要语言上保留整句，
  不把隔着中文的两个英文片段连起来。主次按文字系统和近似字符宽度判断；没有明显多数，
  或不同语言使用同一字母体系时保留整句。日文汉字与假名作为同一文字组处理。
  不提供 UI Automation 选区的应用可使用这个入口。划词热键默认 `Alt+Shift+W`，
  已自定义的热键和明确清空的设置优先。
- 词义窗和完整译文窗根据文字自动调整宽高，最大 720 × 720 逻辑像素，同时限制为当前屏幕可用宽高的 80%；长内容在窗内滚动。固定窗扩展时只在溢出屏幕边界时移动，编辑长原文后保持光标可见。
- 词义窗不抢原应用焦点，未固定时点击外部关闭，不受截图贴图的关闭设置影响；
  固定时保留，复制、重试、关闭使用 WinShun 控件和图标。窗口与截图任务分别取消，
  新的词义请求立即取代旧请求；固定状态只在本次窗口开启期间保留。
  “重试”保留原请求的窗口和取词位置，弹窗不会跟随重试按钮处的鼠标逐次下移。
- 鼠标 OCR、剪贴板和划词窗口的原文默认可编辑，直接点击原文即可修改；
  原文保持正文样式和面板底色，聚焦时只有文字光标闪烁，不显示下划线或输入框高亮。
  自动翻译、译文和加载状态始终保留。失去焦点自动提交，Enter 立即提交，Shift+Enter 换行，
  有草稿时 Esc 或原文末尾的还原图标放弃修改；提交后可继续编辑，无需切换模式。
  打开窗口时不抢焦点，点击原文后才接受键盘输入；有未提交的修改时暂停固定窗口
  的选区跟随，提交或还原后恢复。仅点击原文不会暂停跟随，旧请求不会覆盖新的译文。
- 多屏分别创建完整原生蒙版，采用物理坐标；选区图像一直保持原像素尺寸。
- 框选画面在后台 DIB 合成，每帧仅一次 BitBlt 显示；选区直接按原坐标复制，
  连续拖动不先刷灰，也不把整屏画面缩放到选区。
- 识别和翻译期间显示动画；工具条、设置、提示和语言菜单复用 WinShun 控件和 Phosphor 图标。
- 加载提示随贴图尺寸调整：单词小选区显示 24px 动画，小图使用简短文字，
  较大区域使用 12px 状态文字。小选区的提示放在边缘外，拖动和缩放时同步跟随。
- 贴图为 WinShun 的 Win32 分层窗口，拖动同步工具条，滚轮缩放，Ctrl+滚轮调透明度。
  Esc、双击或关闭按钮立即关闭；点击外部关闭可配置，内部菜单和设置不触发关闭。
- 对照上下排列，默认译文在上，顺序可在基础插件设置中修改。右键可复制、对照、保存或重新截图。
  大图可通过滚轮缩小；长译文可在“完整译文”窗口查看、选中并复制。
- 小型 QML 控件采用软件绘制，不建立每个窗口的 D3D 堆；宿主选择 GPU 渲染不影响这些控件。

主渠道、共用代理、热键和偏好仍由 WinShun 基础插件面板管理。渠道配置页为平铺换行标签，
浏览和保存配置不会切换主渠道。宿主基础卡片的长渠道组是否平铺仍由宿主版本决定；
现有本地宿主修复见 `.host/`，原生包不修改 WinShun.exe。

## 服务和数据

渠道包括 MyMemory、Google、Edge/Bing、translate.js、搜狗、有道、ECDICT、Microsoft、DeepL、
AI 翻译。OpenAI、DeepSeek、豆包、混元等兼容服务统一填写 URL、API 密钥和模型名；旧配置自动迁移。
Google 保留浏览器请求头及多客户端重试；Edge 缓存七分钟凭据，取票
失败后尝试 Bing。MyMemory 和 Google 的文字块最多并行四个；全部渠道测试最多并行三个，
未配置密钥的付费渠道跳过，测试不自动降级或改变主渠道。

设置窗口默认进入首页，展示所有渠道、逐项 / 全部测试、耗时、权重与冷却时间。
手动队列支持拖动手柄或上下按钮；自动模式优先排列可用渠道，再按权重从高到低尝试。
主渠道始终在前；自动降级关闭时仅尝试主渠道。保存将渠道配置与队列原子写入同一份 `services.json`，
取消丢弃草稿；切换自动模式不会丢失手动顺序。旧配置默认保留原来的备用顺序。

权重按近期成功率（80%）和成功响应速度（20%）计算。未测渠道初始为 50；成功率与耗时采用
新样本占 30% 的指数平滑，成功率初始先验为 75%，速度分量为 `1000 / (1000 + 毫秒)`。
同分沿用手动顺序。测试与实际请求都记录结果，失败进入原有冷却；显式测试可以立即重试冷却渠道，
成功后解除冷却。词典不支持的文本、未配置和取消不计入统计；配置指纹变化使用独立统计。
权重与失败记忆保存在 `service-health.json`，不保存请求正文、密钥或翻译结果。

搜狗使用公开网页的服务端结果，有道支持免费英汉查词与官方 v3 签名翻译。ECDICT 以独立 Release 附件提供 770,611 个词条，在设置中一键下载后，
按文件索引查找，无网络或 Python 依赖；未收录词和长句可降级，但不标记词典服务故障。

长文翻译取消 10,000 字限制，按句分段并分批请求，显示已完成进度；面板可切换逐句原译对照。每批独立超时，修改原文或关闭立即取消，后续失败保留已完成译文。

截图 OCR 对长图分块识别并保留坐标，深色及低对比背景先作灰度归一化；纯英文内容可与英文语言包结果比较，中英文混排保留原识别。稀疏大图裁剪空白并还原偏移，识别框按 TextAngle 绕图像中心顺时针旋转，原生行编号用于截图拼接；跨瓦片后重新按全图坐标分组。小字补充放大识别，短标签失败时补试原始边界及画面。

自动降级默认开启。失败时间和配置指纹沿用 `service-health.json`，故障至少冷却 1 小时，连续失败指数退避至最长 7 天；429 遵循 Retry-After，否则从 15 秒开始加倍至 30 分钟；额度耗尽至少 6 小时，认证失败至少 24 小时。
冷却结束后在下一次翻译重试，手动测试可提前恢复；修改地址、代理或密钥使用新的配置状态。
修改 AI 模型、有道应用 ID 或 Azure 区域也会立即重试。
网络请求有总时限并每 25ms 检查取消；关闭窗口立即取消任务，不等待 HTTP 超时。
使用官方翻译插件同类的 Windows WinHTTP 异步请求和系统 HTTPS，宿主不需要 Qt TLS 插件。
划词在显示弹窗前记录原窗口，标准 Edit / RichEdit 控件读取公开选区消息；主动翻译共用原生 WM_COPY、WM_APPCOMMAND 及可还原的剪贴板事务；Firefox 被动检测仍用 IAccessible2，其他应用用
UI Automation，依次查找原控件、鼠标处、焦点及页面内部支持文本选区的容器，兼容
Chromium/Electron 中焦点停留在外层容器的情况。读取使用无窗口的原生辅助进程，
2.2 秒超时或关闭时回收；单次应用卡住不会阻塞后续划词。同一时间至多一次读取；
首次读取为空时，在同一次热键内间隔 150ms、300ms 最多自动补读两次，成功后立即继续翻译。
明确的权限不足或管理员权限提示不会重试，避免掩盖访问限制。过期请求仍会取消并丢弃结果，
主动翻译在读到非空选区后，允许在原焦点、活动输入桌面且无按键按下时使用 Ctrl+Insert；不激活窗口、不占用截图入口。所有主动复制在后台线程完成；取消请求也会完成还原，不强杀复制事务。剪贴板快照保留所有可安全复制的格式；格式无法备份时不发复制命令。只接受目标浏览器的新复制，并只在序列号仍属于本次复制时还原；新复制优先。未公开选区的应用仍可使用鼠标 OCR。
读取失败且检测到权限差异或访问限制时，会提示以管理员身份启动 WinShun 并确认本插件权限。
选区辅助进程直接继承插件权限；授权由 WinShun 管理，普通插件不另行启动提权读取器。

截图留在本机内存；仅 OCR 文字发送到选择或降级的服务。密钥继续由当前用户的 Windows
DPAPI 加密。日志不记录截图、OCR 文字、凭据或服务响应正文。免费入口仍可能限流或失效。
长译文在原区域可能放不下；完整译文窗保留全部文字。复杂背景和不完整的 OCR 框可能留有残影。

## 构建和验证

### 渠道标记与闲置内存

界面渠道名称来自每次请求返回的实际 `provider`，降级标记来自 `fallback`；截图工具栏不截断渠道名称，
词义窗在底部操作旁显示，完整译文和关键字结果同样标记。不会将主渠道配置当作成功结果的来源。
降级时使用 WinShun 的 `caution` 提醒色，正常结果保持默认颜色；每次新请求清除旧降级状态。
渠道悬浮提示使用独立、不抢焦点的 QtQuick 窗口，避免被 32px 工具栏裁切，显示备选渠道及恢复规则。
词义窗修改原文后，在失去焦点时短暂延后提交，先让还原 / 关闭操作完成；空白、未修改和输入法组词不会提交。
Enter 仍可立即提交，末尾的还原图标恢复当前结果对应的原文，避免底部重复按钮占用空间。

参考 WinShun `platform/IdleTrim.cpp` 的空闲回收策略：关闭后保留词义窗 20 秒用于连续取词，
空闲时销毁所有不用的 QML 引擎、释放图片和 QPixmap 缓存，延后等待 Qt 删除完成，再由后台线程调用
`SetProcessWorkingSetSizeEx` 交还驻留页。没有退出插件或释放快捷键，不定时重启进程。
窗口可见、固定词义窗、截图 / OCR / 网络 / 选区任务均阻止回收；检测睡眠恢复后保持页面，直到再次使用。
工作集回收与真正释放对象分别记录，不能把提交内存下降与驻留内存下降混为一谈。

`python -B native/test_native.py --memory --build <目录> --runtime <Qt目录> --output <输出目录>`
在独立桌面依次完成复制翻译、真实 Windows OCR 截图翻译、设置开关，等待真实闲置延迟，
记录各阶段总工作集、私有工作集、提交大小、句柄数和闲置后重新打开耗时；另检查固定窗与睡眠保护。

开发构建需要 Python 3。Qt SDK 由 `native/install_qt.py` 下载固定 SHA-256 的官方 6.12.0 MSVC 包并解压；先安装开发依赖 `py7zr==1.1.4`。这些工具不随插件运行。`build.ps1` 自动下载固定提交的 ECDICT 数据、校验 SHA-256 并生成 `data/ecdict.bin`。
已有词库通过校验后复用，不会重复下载；`package.py` 将索引作为独立 Release 附件，插件包仅保留来源校验记录和 MIT 许可。
用户安装后不需要 Python；使用 ECDICT 前在设置中一键下载词库。完整 UI 测试应串行运行，避免测试热键互相冲突。

### 可选 ECDICT 词库

公开 `.wsplugin` 仅含词库元数据与许可。`native/package.py` 另生成 `ecdict-39cfb967-v2.bin` 和校验值，随插件 Release 上传。客户端固定下载 v0.4.5 的这一数据版本；后续更新插件不需要重复下载相同词库。下载以 64 KiB 分块写入 QSaveFile、增量校验 SHA-256，限制大小和跳转域名；完成前不替换已有数据。下载存入 WS_DATA_DIR/dictionaries/ecdict.bin，禁止将数据作为代码加载。未下载时的队列和批量测试显示待下载并跳过，不降低渠道权重。


### 0.4.13 翻译速度

- 普通段落保留上下文，超长内容按句边界合并至每块约 1200 字；逐句对照仍保持每句对应。
- 首批确认可用后，后续最多两批并行，每批最多两个单请求工作线程；结果按原文顺序显示。
- 相同渠道配置、源/目标语言、释义模式及文本的成功结果在内存缓存十分钟，总预算 2 MiB，单条最多 256 KiB；不写入磁盘。手动渠道测试绕过缓存，取消、配置变化及故障冷却仍生效。
- 自动翻译输入防抖缩短至 350 毫秒；Google 的限流、认证错误和超时立即进入已有降级逻辑，避免同一请求重复尝试多个客户端参数。
